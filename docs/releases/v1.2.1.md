# Swarm v1.2.1 — Codex CLI probado en Windows y Linux

Actualización de compatibilidad · 15/10/2026.

## Qué cambia

- Codex CLI 0.162.1 ya no acepta `--full-auto`: se reemplazó por sandbox explícito y
  aprobaciones no interactivas. Charla en `read-only`; fabricación en `workspace-write`.
- Prompts de Codex por stdin, sin depender del límite de argumentos de Windows.
- Un CLI que termina con error ya no se guarda como una respuesta exitosa. El progreso de
  Codex por stderr tampoco se confunde con la respuesta final.
- Si Codex degrada una fabricación a solo lectura, SWARM muestra un error con la indicación
  para configurar el sandbox, en vez de contar que fabricó.
- La migración `0011` actualiza las plantillas Codex estándar ya guardadas, preservando el
  modelo. No pisa comandos personalizados ni afecta otras sillas.
- Conexiones respeta `CODEX_HOME`; sigue comprobando solo existencia del archivo, no validez
  de la sesión. Modelo vacío usa el default de tu CLI.
- Incluye también el catálogo de OpenCode actualizado que estaba en `main` desde septiembre.

**Probado el 15/10/2026:** 191 tests en Linux y 12 regresiones específicas en Windows 11 build
26200, más charla y creación real de un archivo con commit y mesa HTTP 200 en ambos sistemas.
Codex CLI 0.162.1; en Windows se usó el backend nativo `unelevated`. Otras versiones y backends
siguen sin verificar. [Informe técnico](https://github.com/hidr4lisk/swarm/blob/main/docs/codex-cli-audit.md).

## Descargar y actualizar

[Descargar swarm-portable.zip](https://github.com/hidr4lisk/swarm/releases/latest/download/swarm-portable.zip)
(Windows + Linux, ~100 MB). No necesitás Python ni Docker para usar la app.

1. Cerrá SWARM.
2. Reemplazá `app/`, los launchers y los archivos `runtime-*.tar.gz` / `runtime-*.ver` con los
   del zip nuevo. **Conservá tu carpeta `data/` completa**: contiene mesas, sillas y bóveda.
   No la reemplaces por la carpeta vacía de la descarga.
3. Abrí `Enjambre.bat` en Windows o `enjambre.sh` en Linux. El arranque aplica las migraciones;
   si usás el código fuente, aplicá `python manage.py migrate` antes de arrancar el worker.

No se copian logins de CLI entre equipos: Codex debe estar instalado y autenticado en cada PC.
Para `/armar` necesitás **git instalado y el toolbelt encendido**.

## Codex en Windows

Antes de fabricar, configurá el backend nativo en el `config.toml` de Codex. Para QA portátil sin
preparación de administrador se probó:

```toml
[windows]
sandbox = "unelevated"
```

Conserva un token restringido y límites de filesystem, pero aísla menos la red que `elevated`,
que requiere preparación de administrador. SWARM no modifica tu backend ni desactiva el
sandbox. Codex no tiene escritura arbitraria sobre todo el host.
[Guía oficial de Windows](https://developers.openai.com/codex/windows).

## English

Codex CLI 0.162.1 is now tested on Linux and Windows: explicit read-only/workspace-write
sandboxes, stdin prompts, reliable failure reporting, and a data migration for existing standard
seats. Windows needs a configured native Codex sandbox backend; `unelevated` was used for
portable QA, preserving filesystem limits without administrator setup (weaker network isolation
than `elevated`). SWARM does not override that choice.

To upgrade, close SWARM, replace the app/launchers/runtime archives, and **keep your entire
`data/` directory**. Startup applies migrations. CLI binaries and logins stay local to each PC;
building requires git and the toolbelt switch. Tested on 2026-10-15: 191 Linux tests, 12 Windows
regressions, plus real chat and file creation/commit on both platforms.
