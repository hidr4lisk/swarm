# Swarm v1.2.2 — blindaje de las mesas

Actualización de seguridad · 18/11/2026.

## Qué cambia

- **git endurecido** en todo lo que Swarm corre sobre mesas y sillas: sin hooks, sin fsmonitor,
  sin config global ni de sistema. Un repo o una config de usuario con hooks ya no ejecuta nada
  al commitear un turno.
- **Huella del `.git` antes de cada turno**: si una silla altera el `.git`, mete config peligrosa
  o un repo anidado, ese turno no se commitea y la mesa lo muestra.
- **Artefactos sin seguir enlaces** al ver, zipear, subir y escribir `NOTAS.md`. En Linux se usa
  `O_NOFOLLOW` + `dir_fd`. En Windows se rechazan junctions, ADS (`archivo:flujo`), unidades y
  `.GIT` en cualquier caso. Además, después de abrir se verifica la ruta final del handle, lo que
  cierra la carrera junction-entre-mirar-y-abrir.
- **Entorno de la silla por lista blanca**: el CLI de una silla recibe solo la base del sistema,
  proxy/certificados y las variables de su proveedor (`ANTHROPIC_*`, `OPENAI_*`, `CODEX_*`,
  `OPENCODE_*`, `GEMINI_*`…). Ya no hereda `SWARM_SECRET_KEY`, `GITHUB_TOKEN`, `AWS_*` ni `GIT_*`.
  Si tu silla necesita otra variable (p. ej. `GROQ_API_KEY` para opencode), definí antes de abrir
  SWARM: `SWARM_SILLA_ENV=GROQ_API_KEY` (nombres o prefijos con `*`, separados por comas).
- Prompt por stdin también para claude y opencode.
- Un fallo de ejecución de la silla se ve en la mesa en vez de perderse en el log.

**Probado el 18/11/2026:** 249 tests en Linux. En Windows 11 (VM, Python portátil del zip,
PortableGit 2.56.1) se corrieron pruebas en vivo de hooks (repo y global), junctions, ADS, `.GIT`
y repos anidados. También una carrera de junctions de 20 s: antes del parche escapaba 1 lectura en
~254 mil intentos; con el parche, 0 en ~216 mil, y las lecturas legítimas siguen pasando.

## Descargar y actualizar

[Descargar swarm-portable.zip](https://github.com/hidr4lisk/swarm/releases/latest/download/swarm-portable.zip)
(Windows + Linux, ~100 MB). No necesitás Python ni Docker para usar la app.

1. Cerrá SWARM.
2. Reemplazá `app/`, los launchers y los archivos `runtime-*.tar.gz` / `runtime-*.ver` con los
   del zip nuevo. **Conservá tu carpeta `data/` completa**: contiene mesas, sillas y bóveda.
3. Abrí `Enjambre.bat` en Windows o `enjambre.sh` en Linux. Esta versión no trae migraciones.

## English

Security update. Hardened git (no hooks/fsmonitor/global config) is used for every table and
seat. The `.git` is fingerprinted before each turn: tampering blocks the commit and shows in the
table. Artifacts are opened without following links: `O_NOFOLLOW`/`dir_fd` on POSIX; on Windows,
junctions, ADS, drives and `.GIT` are rejected, and each opened handle's final path is verified,
which closes the junction race. Seat CLIs now get a whitelisted environment (OS base,
proxy/certs, their provider's variables); add more with `SWARM_SILLA_ENV`. Tested on 2026-11-18:
249 Linux tests plus live Windows 11 checks (0 escapes in ~216k race attempts). To upgrade,
replace app/launchers/runtime archives and **keep your `data/` directory**; no migrations.
